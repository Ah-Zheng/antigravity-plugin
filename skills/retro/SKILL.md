# Retrospective（對話復盤與持續演進協議）

> 「不要讓犯過的錯誤白白浪費；將除錯痛點轉化為專案的自動化防護網。」

本協議改寫自 Matt Pocock 之工程標準，旨在一個工作階段結束後，檢視 AI 助理在過程中的表現，並針對**「專案開發環境、自動化檢查、程式碼規範」**提出升級建議，讓未來的協作越來越順暢。

---

## 復盤四大檢視維度 (The 4 Review Lenses)

在執行復盤時，AI 必須從以下四個維度逐一審視剛才的對話與操作：

### 1. 導航與資訊盲點 (Navigation & Access)
- AI 在尋找關鍵檔案時是否花費了過多步驟？
- 檔案之間是否存在隱藏依賴（如動態 import 或缺乏型別關聯）？
- **改進方案**：是否需要在專案根目錄的 `README.md` 或 `AGENTS.md` 加入關鍵導航指引（Navigation Pointers）？

### 2. 自動化檢查機會 (Automated Guardrails)
- 剛才 AI 犯下的語法、型別或依賴錯誤，是否本該被自動化工具擋下？
- 專案是否缺少 Pre-commit hook、CI 測試或 Linter 規則？
- **改進方案**：將剛才踩坑的規則寫進 ESLint / TypeScript 設定或 Pre-commit 腳本中，而非僅依賴人類口頭提醒。

### 3. Reviewer 規範強化 (Coding Standards)
- 本次修改中出現的壞味道，是否有特定的模式可以規範？
- **改進方案**：更新專案的 `CODING_STANDARDS.md` 或 AI Prompt 規則，加入明確的壞味道範例與正向推薦。

### 4. 工具經濟與 Token 耗損 (Tool Economy)
- 剛才是否有發起過度冗長的目錄遍歷、全文讀取大型檔案等昂貴的無效呼叫？
- **改進方案**：如何優化後續指令以節省 Token 與思考時間？

## 復盤產出格式

向使用者呈現精簡復盤卡片：

```text
📋 [SESSION RETROSPECTIVE] 本輪協作復盤報告

🎯 本次任務成果回顧：[簡述完成的功能或修復的 Bug]

💡 專案環境與規範升級建議（按重要性排序）：
1. 🛡️ 【自動化防護】[建議新增的 Linter / Typecheck / Hook]
2. 🧭 【檔案導航】[建議新增或調整的架構說明]
3. 📝 【規範更新】[建議寫入 CODING_STANDARDS 的新條款]

❓ 是否需要我立即為你將上述第 X 點直接寫入專案相應設定中？
```
