# Wiki Onboarding（專案解讀與上手全覽）

自動掃描專案程式碼與設定檔，產出兩份互補的專案導讀文件，讓工程師能迅速建立對專案的深度理解。

## 觸發時機
- 接手全新專案或跨專案支援
- 要求產生 Onboarding 文件、架構導覽或新手入門手冊
- 需要快速理清專案核心脈絡與技術架構

## 語言與技術棧偵測

掃描專案根目錄的建置檔案，自動決定範例程式碼語言與框架慣例：
- `package.json` / `tsconfig.json` → TypeScript / JavaScript
- `Cargo.toml` → Rust
- `pyproject.toml` / `requirements.txt` → Python
- `go.mod` → Go
- `pom.xml` / `build.gradle` → Java / Kotlin
- `*.csproj` / `*.sln` → C# / .NET

## 指南一：架構師級專案全覽（Principal-Level Overview）

**目標客群**：資深工程師、架構師，專注於「為什麼這樣設計（Why）」與系統邊界。

### 必備核心章節
1. **系統核心哲學與設計原則**：系統維護哪些不變量（Invariants）？核心設計決策是什麼？
2. **架構全景圖**：使用 Mermaid 流程圖標註核心模組權限邊界與通訊模式。
3. **關鍵抽象與介面**：支撐全系統運作的骨幹 Class、Interface 或資料結構。
4. **資料流與狀態轉移**：追溯核心業務資料在系統各層之間的流向（由真實程式碼驗證，禁止猜測）。
5. **重要依賴項選型理由**：核心外部套件選用目的及其封裝邊界。
6. **已知技術債與系統瓶頸**：誠實盤點目前的妥協點、潛在效能熱點與修復建議。

### 撰寫規範
- 每個核心主張須附帶行號引用：`(path/to/file:line)`。
- 至少包含 1~2 張 Mermaid 架構圖。
- 著重在「決策脈絡（Why）」而非單純檔案清單條列。

#### 🛡️ Mermaid 架構圖語法防爆鐵律（Zero-Error Rules）
為防止 Markdown 渲染器與各類 IDE 解析崩潰，所有生成的 Mermaid 圖表必須 100% 遵守以下約束：
1. **節點標籤強制雙引號包裹**：任何節點名稱、說明文字只要含有括號 `()`、方括號 `[]`、花括號 `{}`、斜線 `/`、冒號 `:`、空格或特殊字元，**一律強制使用雙引號包裹**。
   - ❌ 錯誤：`A[身份驗證 (JWT Auth)]`、`DB[(資料庫 (PostgreSQL))]`
   - ✅ 正確：`A["身份驗證 (JWT Auth)"]`、`DB[("資料庫 (PostgreSQL)")]`
2. **嚴禁使用保留字作為節點 ID**：
   - ❌ 錯誤：`start --> process --> end`（`end` 為 Mermaid 區塊結束關鍵字）
   - ✅ 正確：`step_start["開始"] --> step_process["處理"] --> step_end["結束"]`
3. **Subgraph 必須具備安全 ID 與引號名稱**：
   - ❌ 錯誤：`subgraph User Service`
   - ✅ 正確：`subgraph UserService ["User Service (使用者服務)"] ... end`
4. **連線標籤格式標準化**：
   - 一律採用 `-->|"標籤內容"|` 語法，文字同樣加上雙引號，避免符號衝突。
5. **避免使用未轉義之 HTML 標籤**：
   - 嚴禁在節點內混用 `<br>`、`<div>`、`<span>` 等 HTML 標籤，多行請改用雙引號內的多行文字或以簡短標籤代替。

## 指南二：新人 0 到 1 上手指南（Zero-to-Hero Contributor Guide）

**目標客群**：第一天接手專案的新成員，專注於「如何跑起來與動手改（How）」。

### 必備核心章節
1. **專案一句話定位**：2~3 句話講清楚專案解決什麼問題。
2. **開發環境準備**：前置依賴工具、版本需求與環境變數設定。
3. **專案目錄導覽**：標註主要目錄用途與重要檔案入口。
4. **第一次動手修改範例**：端到端演示新增一個最小功能或修復 Bug 的標準流程。
5. **測試與驗證**：如何執行測試、建置指令與預期的成功輸出。
6. **常見踩坑清單（Common Pitfalls）**：新手最容易犯的錯誤與解法。
7. **速查卡（Cheat Sheet）**：最常用的 5 個終端指令。

### 撰寫規範
- 所有指令必須可直接複製貼上執行。
- 提供驗證各步驟成功的檢查標準。
