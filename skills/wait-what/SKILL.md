# Wait What（溝通急煞車協議）

> 「等等，我聽不懂你剛剛在講什麼。立刻停止，用大白話重新說一遍。」

本協議改寫自 Matt Pocock 之同名技能，專為消除「AI 講話過度囉嗦、抽象、黑話堆疊或偏離使用者思維軌道」時的認知過載（Cognitive Overload）而設計。

---

## 觸發時機
- 使用者輸入 `/wait-what` 或說「等等我聽不懂」、「講重點」、「說人話」時。
- 使用者感到資訊量過大、無法消化剛才那段長篇大論時。

---

## AI 強制執行規範

一旦觸發此技能，AI 必須**立刻捨棄**剛才那種冗長或抽象的表達方式，嚴格遵守以下四項重述紀律：

1. **直接重開頭，無客套與道歉**：
   - 嚴禁說「抱歉我講得太複雜了」、「對不起讓您困擾了」等客套廢話。
   - 直接用一句話破題：「**核心一句話：[最核心的結論/事實]**」。

2. **強制採用「極簡技術白話」（Simplified Technical Language）**：
   - 禁用空洞的架構行話與華麗修辭。
   - 每個句子控制在 25 字以內，語意直白清晰。

3. **統一專案領域術語**：
   - 使用當前專案中真實存在的函式名、檔案名與名詞，不自行生造抽象名詞。

4. **極簡卡片重現**：
   - 最多 3 個條列點，標註：
     - **目前做到哪**：現在的真實狀態
     - **卡在哪 / 問題是什麼**：具體障礙或分歧點
     - **下一步需要你決定什麼**：給出 1~2 個明確選項

---

## 輸出範本

```text
🛑 [急煞車重整]

📌 核心一句話：
我們現在是要把「購物車資料」從目前瀏覽器的 LocalStorage 搬移到後端的 Redis，目的是讓使用者換裝置登入後購物車不會消失。

🔍 3 個關鍵現況：
1. 目前進度：已讀完購物車前端元件與後端 API 檔案，確認上下游沒問題。
2. 核心考量：登出時，這台裝置尚未綁定帳號的購物車資料是否要合併到會員帳號？
3. 下一步行動：
   - 選項 A：自動合併（最符合電商常理）
   - 選項 B：直接覆蓋（實作最單純）
```
